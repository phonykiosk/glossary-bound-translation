# GlossaryBoundTranslation design and test plan

AI-assisted prototype; no live deployment claim. Owner registers a bounded bilingual scope consisting of 1..8 exact source/target clause selections, commit-pinned document byte digests, declared language tags, terminology pairs and literal code tokens. Source is UTF-8 text; target is singular, non-fuzzy GNU PO msgstr text. Headers, msgid, fuzzy and plural entries cannot supply target evidence.

Each clause is assessed once. Independently fetched bytes must match the locked hashes; deterministic code-token, glossary-presence and numeric-literal invariants run before semantic evaluation. English zero..nine normalize to digits; other numeric notation must match exactly (conservative false negatives are possible). Validator independently re-fetches, re-parses and re-evaluates meaning, qualifiers, obligations, negations and terminology. MATCH / MISMATCH / UNCERTAIN is finite; uncertainty cannot seal. An entire bundle fingerprint is unique, including after withdrawal, so changing its ID cannot reroll an assessment.

Seal requires every declared clause MATCH and a fresh independently verified source snapshot. It yields an immutable scope receipt; owner withdrawal invalidates current authority without deleting history. This is a declared excerpt translation signal, not full-document coverage, certified translation or proof about underlying factual truth. Consumers bind scope hash and check current status.

TDD first runs real official direct SDK behavior tests against a minimal contract. Use recorded actual Python 3.14 English/Chinese pinned documentation and a synthetic altered translation explicitly marked as adversarial. Tests cover real msgstr decoding, independent disagreement, msgid confusion, fabricated citations, critical tokens, glossary and number failures, state ordering, terminal single assessments, unique scope fingerprints, source changes and owner withdrawal. Full exact SDK lint/semantic validation/schema follow.
